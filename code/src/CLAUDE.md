# CLAUDE.md — code/src/

Read order: `.claude/CLAUDE.md` → `.claude/MEMORY.md` → this folder's `CONTEXT.md` (the track map and
what each folder holds, imported above) → this file → the track's own `CONTEXT.md` and `CLAUDE.md`
(`c/`, `rust/` or `scripts/`).

## Purpose (one line)

The source root: every exercise, crate and gate script in the repository, one folder per track, all held
to the same gates locally and in CI.

## How to work here

- **Routing:** C work → `c/`; Rust work → `rust/`; a gate, audit or wrapper script → `scripts/`. New
  work enters through a procedure in `code/workflows/` — `01-c-exercise/`, `02-tdd-cycle/`,
  `03-rust-exercise/`, `04-ffi-bridge/` to build; `05-review/` and `06-memory-check/` to verify;
  `07-debug/` and `08-refactor/` to diagnose and improve.
- **Tutor mode:** before helping with an exercise, ask the learner how they plan to approach it. Explain
  and ask guiding questions; do not write exercise solutions unless explicitly asked. In a review, point
  at the relevant `code/docs/` section rather than rewriting the learner's code.
- **Raw command first, script second:** show the command the learner would type (`make -C code/src/c
  test`, `cargo test` inside `code/src/rust/`), then name the script that wraps it. Claude's own
  verification runs the scripts, because they report a missing tool as COULD NOT RUN instead of a pass.
- **Concrete steps:** descend to the track and read its `CONTEXT.md` → follow the matching
  `code/workflows/` procedure → run the track's gates → `bash code/src/scripts/gates/all.sh` before
  calling the work finished → update every `CONTEXT.md` whose tree or tables changed.
- **Definition of done:** every gate in `code/src/scripts/gates/all.sh` passes (the procedure is
  `how-to/workflows/03-quality-gates/`); every new directory has its `CONTEXT.md` + `CLAUDE.md` pair, or
  sits in an exempt class (`code/docs/DOCUMENTATION-PAIRING.md`); British English throughout.

## Guardrails

- **Pair every new directory.** A new exercise, crate or script group gets its `CONTEXT.md` +
  `CLAUDE.md` in the same change; `code/src/scripts/audits/docs-pairing.sh` fails the build otherwise.
- **Keep each source file at or under 750 lines.** Past that, split it into smaller files or modules.
- **Fix warnings; never silence them.** Every C warning is an error and clippy runs at `-D warnings`;
  the answer is a code change, not a dropped flag, a `#pragma` or an `#[allow]` without a reason.
- **Create `kernel/`, `os/`, `python/` and `cuda/` only when their phase starts.** P4, P6, L1 and L2
  respectively (`project-management/src/01-ROADMAP/ROADMAP.md`); until then they are planned rows, not
  folders. Python package naming is decided at L1.
- **Keep exercises small here.** A substantial build — the downstream kernel tree, the Syntek OS build
  system and tools, the LLM's data, training and inference code — goes to its own repository when its
  build starts, never into this tree.
- **Run custom kernels and modules in QEMU only, and OS images in VMs.** Never install or `insmod` one
  on the host — the non-negotiables are owned by `.claude/CLAUDE.md`.
- **Never commit build output.** `build/` and `target/` are regenerated by every build and are
  gitignored; kernel source trees, disk images, model weights, checkpoints and datasets are never
  committed either.

## Output & naming

- **Hand-written:** C sources, headers and Makefiles under `c/`; crates, manifests and policy files
  under `rust/`; scripts under `scripts/`; every `CONTEXT.md` and `CLAUDE.md`.
- **Generated (never hand-edit):** each exercise's `build/`, the workspace's `target/`, and
  `rust/Cargo.lock` (written by cargo, committed as generated).
- C exercise folders `msNNN-kebab-name/`; Rust crate folders `msNNN_snake_name/` matching the package
  name; scripts `kebab-case.sh`; other source folders `kebab-case/`; documentation
  `SCREAMING-SNAKE-CASE.md`.
- **Exercise numbering (this file owns it):** `NNN` is the milestone the work belongs to (the number
  in its `EX-MS###` spec, where it has one). A Rust port keeps the C exercise's number and name,
  converted to snake case (`ms001-hello` → `ms001_hello`), so the pair sorts together; a new
  Rust-only exercise takes its own spec's milestone number. Several exercises may share one
  milestone's number, told apart by the name.
