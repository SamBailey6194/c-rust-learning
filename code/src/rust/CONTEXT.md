# code/src/rust/ — The Rust Track

**Last Updated**: 27/09/2026

One Cargo workspace holds every Rust crate in the repository. Each exercise is a member crate under
`crates/`, and the workspace root holds everything the crates share: one lock file, one `target/`
folder, one pinned compiler, one lint policy and one supply-chain policy — written once, so the policies
cannot drift apart between exercises. At P1 the workspace holds the Rust twin of the first C exercise;
P3 deepens the track (ownership, traits, errors, concurrency, `unsafe`) and adds the FFI crates that
join C and Rust. The edition and the pin are recorded in
`project-management/src/08-DECISIONS/ADR-MS001-RUST-EDITION-2024-TOOLCHAIN-PIN-27-09-2026.md`.

## Directory Tree

```text
code/src/rust/
├── CONTEXT.md · CLAUDE.md   ← this file · how to work on the Rust track
├── Cargo.toml               ← [workspace]: members, resolver 3, shared package facts, the lint policy
├── Cargo.lock               ← the resolved dependency graph — generated by cargo, committed
├── rust-toolchain.toml      ← the pinned compiler (1.92.0, rustfmt + clippy) rustup reads here
├── clippy.toml              ← lint tuning: unwrap() and expect() allowed inside tests
├── rustfmt.toml             ← edition = "2024", so bare rustfmt formats like cargo fmt
├── deny.toml                ← cargo-deny policy: advisories, licences, bans, sources
├── crates/                  ← one folder per crate (covered by this pair)
│   └── ms001_hello/         ← MS001 — the Rust twin of code/src/c/ms001-hello/
└── target/                  ← cargo's build output, gitignored
```

## Crates

| Crate | Twin of | Practises |
| --- | --- | --- |
| `ms001_hello` | `code/src/c/ms001-hello/` | a library crate and a binary crate in one package, `String` against a C buffer, unit, integration and doc tests |

Crate folder and package name are the same snake_case word. A package name cannot start with a digit,
so exercises take an `msNNN_` prefix: a port keeps the number of the C exercise it sits beside, and a
new Rust-only crate takes its spec's milestone number (`code/src/CLAUDE.md` → Output & naming).

## The lint policy is the doctrine

`Cargo.toml` sets the policy once in `[workspace.lints]`, and each crate opts in with
`[lints] workspace = true`:

| Lint | Level | Why |
| --- | --- | --- |
| `unsafe_code` | deny | `unsafe` is on the syllabus (FFI, P3), so it is denied rather than forbidden: a crate that needs it writes a visible `#[allow(unsafe_code)]` on the smallest item, with a `// SAFETY:` comment naming the invariant |
| clippy `all` | deny | every default clippy lint is an error |
| clippy `pedantic` | warn | opinionated lints that teach; CI's `-D warnings` still requires them clean |
| `unwrap_used`, `expect_used` | warn | a panic on the unhappy path; allowed inside tests by `clippy.toml`, where a panic is the failure report |

## The pin follows the current directory

rustup finds `rust-toolchain.toml` by walking up from the **current directory**, not from the manifest.
Commands run inside `code/src/rust/` use the pinned compiler; `cargo test --manifest-path
code/src/rust/Cargo.toml` run from the repository root uses whichever toolchain is the default there.
Both run the same tests, but only the first is guaranteed to match CI, which is why the wrapper
scripts change into this folder first.

## Licences in a GPL-2.0-only repository

The repository is GPL-2.0-only, like the Linux kernel, so a dependency linked into a binary here has to
be GPL-2.0-compatible. `deny.toml` allows permissive licences (MIT, BSD-2-Clause, BSD-3-Clause, ISC,
Zlib, Unicode-3.0) and leaves out Apache-2.0 on its own, which the Free Software Foundation considers
incompatible with GPL version 2 (<https://www.gnu.org/licenses/license-list.html#apache2>). Most crates are "MIT OR Apache-2.0" and pass on their MIT side. At
baseline the workspace has no third-party dependencies at all.
